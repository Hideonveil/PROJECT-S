# PROJECT-S 首页视觉匹配状态设计

## 目标

在首页“摇人”筛选完成后提供一个全屏视觉匹配状态。该状态复用现有实时统计，但不创建匹配请求、不写入后台。

## 进入流程

- 用户先打开摇人筛选面并完成游戏、模式、时间、人数和语音选择。
- 点击筛选面右下角“摇人”后，停留在首页，不跳转旧认证页或现有匹配路由。
- 筛选标题、说明、选项和按钮同步淡出并稍微拉开字距，随后完全隐藏。
- 黑色斜面的两条平行边同时向外扩张，最终铺满整个视口。
- 扩张动画使用相同顶点数量的 `clip-path` 渐变，避免形状直接跳变。

## 匹配状态

- 全屏背景沿用摇人面的黑色和点阵质感。
- 屏幕中央显示一个手柄图案。
- 手柄使用持续、匀速、无限循环的旋转动画。
- 手柄下方显示“正在摇人”状态文字。
- 页面下方显示三类信息：
  - 当前匹配池人数，读取 `state.match.pool`。
  - 当前正在游戏人数，读取 `state.match.playing`。
  - 用户本次选择的游戏、模式、时间、人数和语音需求。
- 人数为 `0` 时如实显示 `0`，不伪造演示数字。

## 需求摘要

- 用户点击最终摇人按钮时，从当前筛选面中读取每个分组的选中项。
- 摘要仅保存在当前 DOM 视觉状态中。
- 不修改全局 `state.need`，不调用匹配 API，也不写入本地正式账号数据。

## 退出匹配

- 全屏状态提供清晰可见的“退出匹配”按钮。
- 点击后停止手柄旋转，匹配内容淡出。
- 黑色全屏面沿原路径收回，随后关闭摇人层并恢复完整主页。
- 退出后不进入认证页、不保留匹配请求、不产生后台记录。

## 动画与可访问性

- 文字退场与斜面扩张按顺序衔接，避免所有元素同时跳变。
- 手柄旋转不影响退出按钮的可点击性。
- 用户开启减少动态效果时，直接切换到全屏最终状态，手柄不旋转。
- 所有状态文字和退出按钮保持键盘可访问。

## 不在本阶段处理

- 发起真实匹配请求。
- 登录校验和账号绑定。
- 匹配成功、候选玩家或 Session 创建。
- Supabase、数据库、RLS 和线上部署。

## 验收

- 选完需求点击“摇人”后，筛选文字完整退场。
- 斜面从两边同时扩张并铺满视口。
- 手柄在中央持续旋转。
- 下方显示真实匹配人数、真实游玩人数和完整需求摘要。
- 点击“退出匹配”可以恢复主页。
- 原有社区、我的、登录和注册视觉流程继续可用。
