# 机缘 MVP 人工全量自检清单

每次正式发布前，用两台电脑或两个互不共享登录状态的浏览器窗口，准备账号 A、账号 B。所有条目以“页面不整页刷新、状态能自动同步、没有回到旧页面”为共同通过标准。

## 0. 测试准备

- [ ] 正式域名 `https://jiyuan.online` 证书正常，无浏览器安全警告。
- [ ] OPS 可登录，记录当前线上版本号、在线人数、摇人人数、游玩中人数。
- [ ] 浏览器 A、B 分别清缓存后打开；再准备一个未登录无痕窗口。
- [ ] 打开浏览器控制台和网络面板，整个测试期间无持续红色错误、无重复请求风暴。

## 1. 首次进入与 Hero 首页

- [ ] 第一次打开时紫色加载画面覆盖白屏等待，结束后平滑进入 Hero。
- [ ] Logo、名称“机缘”、Slogan、警戒线均正确，Logo 不被压扁。
- [ ] 页面滚动不超过约一页半；摇人入口在视口内，只有悬停时轻微抖动。
- [ ] 点击 Logo 回到 Hero；登录、注册入口可用；移动端明确提示使用电脑访问。

## 2. 注册、登录与身份创建

- [ ] 注册必须输入两次密码；两次不一致、弱密码、重名均给出可理解提示。
- [ ] 密码眼睛位置正确，睁开/闭合只改变密码可见性，不改变布局。
- [ ] 登录与注册切换丝滑，表单、底部 Loop、侧栏均不跳动。
- [ ] 身份创建逐步完成：昵称、头像上传/无头像、设备、游戏类型、性别。
- [ ] 步进器连续、不闪烁；刷新或后退不会生成半成品身份。
- [ ] 性别页显示“当前版本会优先匹配同性玩家”。
- [ ] 登录后右上角显示 ID 和登出；登出回到当前新版首页，不出现旧 UI。

## 3. 导航与基础页面

- [ ] 左侧导航默认收起只显示图标，悬停展开，移开收回。
- [ ] 展开时连续点击摇人、社区、我的、朋友，导航不闪两次、不先缩后展。
- [ ] 登录/未登录头像均保持正圆或原始比例，不被横向压扁。
- [ ] 社区显示 Coming Soon；我的、朋友、最近连接均进入新版页面。
- [ ] 房间内点击导航不会意外跳出有效房间或回到旧页面。

## 4. 摇人配置

- [ ] 初次进入先显示游戏选择，不直接进入 Deadlock 配置。
- [ ] 王者荣耀、无畏契约、我的世界显示 Coming Soon；Deadlock 可继续。
- [ ] 上分流程：目的 → 段位 → 我的位置和希望队友位置 → 麦克风。
- [ ] 位置支持多选，“可多选”明显；不限与具体号位互斥。
- [ ] 段位完整且顺序正确；Deadlock 官方组队硬规则不可被等待时间突破。
- [ ] 娱乐流程只保留队友人数和麦克风；队友人数选项只显示数字。
- [ ] 上分/娱乐切换只更换当前配置与步进器，不整页刷新。
- [ ] 下一步、上一步、返回选择游戏、开始匹配按钮完整可见，没有右侧裁切。
- [ ] 目标光标只作用于选项，不影响返回、下一步、开始匹配。
- [ ] “联系我们”按钮可见、可键盘聚焦，点击打开新窗口。

## 5. 联系我们与 OPS 收件箱

- [ ] 未登录无痕窗口点击“联系我们”会被引导登录，不能提交反馈。
- [ ] 已注册玩家可以提交；少于 10 字或超过 500 字时不提交并给出提示。
- [ ] 选择发现问题/功能建议/其他，填写正文和可选联系方式后只出现按钮内“提交中”。
- [ ] 提交不出现全屏加载，不发送邮件，成功后提示已进入运营台。
- [ ] OPS 最迟 30 秒自动出现新记录；切回 OPS 标签页也会立即刷新。
- [ ] OPS 显示类型、注册玩家、时间、正文和联系方式；不显示内部路由或游戏字段。
- [ ] 用户输入的换行和长文本可读，不撑破布局；OPS 未登录者无法读取收件箱 API。

## 6. 实时匹配池与异常操作

- [ ] 只有 A：保持 searching，等待时间连续增长，10 秒后不刷新清零。
- [ ] A、B 条件相符：双方都自动看到候选，而不是只有后进入者看到。
- [ ] 软偏好不完全一致：仍可按当前简单策略形成候选；硬规则不符：绝不匹配。
- [ ] 同一账号重复点击开始匹配只产生一个有效请求。
- [ ] 一方 searching 时取消，立即从池中消失；另一方不能再匹配到幽灵请求。
- [ ] 找到候选后一方拒绝，双方退出该候选状态；一方超时只显示结果，不整页刷新。
- [ ] 一方接受后另一方显示“对方已接受”；不要求两人同一瞬间点击。
- [ ] 双方接受后自动进入同一房间；已匹配玩家不再出现在池中。
- [ ] 断网、关闭标签、重新打开后恢复正确状态；过期请求从池中移除。
- [ ] 完成或正常关闭后，同一对玩家可以再次匹配。

## 7. 房间实时闭环

- [ ] 双方进入的是同一房间，成员、模式、位置、麦克风信息一致。
- [ ] A 输入游戏账号后，B 无需刷新即可看到；复制按钮复制正确内容。
- [ ] 添加机缘好友：申请实时出现在对方房间，对方可接受/拒绝，状态双方同步。
- [ ] 页面刷新或短暂掉线后仍回到当前房间，不回旧页面。
- [ ] “拜拜”按钮明显；一方点击先二次确认，另一方看到是谁提出拜拜并可回应。
- [ ] 双方拜拜后房间正式关闭并进入结束页；一方异常退出标记为异常，不计正常完成。

## 8. 结束页、评价与关系沉淀

- [ ] 结束页显示双方、游玩信息、点赞入口和体验评价。
- [ ] 点赞和评分点击后立即出现本地选中态，后台慢时也不延迟卡顿；失败时能回滚并提示。
- [ ] 非好友显示“加好友”，已是好友显示“已是好友”；申请与接受状态准确。
- [ ] 提交评价只写一次，重复点击不产生重复数据。
- [ ] 最近连接出现本次玩家；朋友列表使用“朋友列表”，没有旧的“开始匹配”入口。

## 9. OPS 与数据一致性

- [ ] OPS 密码可修改；旧密码失效，其他设备会话退出，当前设备保持登录。
- [ ] OPS 每 30 秒静默刷新，手动刷新可用，刷新时页面不闪白。
- [ ] 在线、摇人中、游玩中口径正确：游玩中来自有效 Session，不来自残留房间壳。
- [ ] 0 在线时不会因历史房间显示 1 人游玩中；数据随实际状态及时下降。
- [ ] 漏斗、趋势、错误、反馈均随 7/14/30/90 天切换。
- [ ] 检查数据库：每个用户最多一个活跃匹配请求；无过期 ticket、孤立 pair、幽灵 room member。

## 10. 兼容性、性能与可用性

- [ ] Chrome、Edge、Safari 最新版各走一遍 Hero → 登录 → 摇人 → 退出。
- [ ] 1366×768、1920×1080 下按钮和表单无裁切；缩放 125% 仍可操作。
- [ ] Tab 可依次聚焦所有交互，焦点轮廓清楚；Esc/X 可关闭弹窗（若该弹窗定义了关闭）。
- [ ] 开启“减少动态效果”后核心流程可用，没有强制旋转或快速闪烁。
- [ ] 首屏无长白屏；接口慢时有局部反馈；小操作不使用全屏转场。
- [ ] 浏览器刷新、前进、后退不会进入退役路由或旧 UI。

## 11. 发布与回滚

- [ ] `typecheck`、单元测试、生产构建、E2E 全部通过。
- [ ] Git 提交、GitHub 分支和服务器版本号一致，工作区无未提交改动。
- [ ] `/api/health` 返回 ready，数据库延迟正常，HTTPS 与域名正常。
- [ ] 发布后用正式域名做一次 A/B 双人真实闭环，不只检查首页。
- [ ] 保留上一个可用镜像/提交号；发现 P0（不能登录、不能匹配、数据串用户、无法退出）立即回滚。

## 上线判定

- P0 必须为 0；P1 必须有明确负责人和修复时间。
- 双人闭环至少连续成功 3 次，其中一次包含取消重来，一次包含断线恢复。
- OPS 能看到本次搜索、匹配、完成、评价与联系我们记录，才算真正通过。
